# 答辩演示脚本（E10-T7）

> 5 分钟主线：**排行榜（切中文集）→ 实验 → 逐题网格 → 单题证据**。一条线讲清"这个平台怎么给 AI 打分、分数从哪来、能不能复核"。
> 数字和链接全按开发库 2026-09-21 晚的状态写（最终实验 #158–#170 跑完之后），演示前照 §0 核一遍。
> 前端 `http://localhost:3000`、后端 `http://localhost:8000`；compose 部署默认同端口。

## 0. 开场前 15 分钟：检查清单

按顺序打勾，一条都别跳——每条后面都是踩过的坑。

- [ ] **退出 Docker Desktop**（AGENTS.md §10）。`docker info --format '{{.Name}} {{.DockerRootDir}}'` 要是 `DESKTOP-D3QQNH3 /var/lib/docker`，不是的话 docker 连到了另一个守护进程，镜像和容器会"凭空消失"。
- [ ] 数据库起着：`make db-up`，然后 `docker ps --format '{{.Names}} {{.Status}}' | grep bench-postgres`。
- [ ] 后端 + 前端：`make dev`（后端 :8000 + 前端 :3000）。首页底部"平台自检"四行全绿（服务状态 ok · 数据库 ok · 迁移版本 0008 · 评测协议 v1.2）。
- [ ] **`.env` 里 `BENCH_BLIND_REVIEW` 是 `false` 或留空**。开着的话单题页的"失败归因"区块只显示"盲检进行中"，主线第 4 步讲不了。改了要重启后端。
- [ ] 没有 Worker 在跑：`ps -eo args | grep '[a]pp\.worker'` 为空。主线不现场跑实验，不需要 Worker；万一有残留 Worker 起了容器会吃内存。
- [ ] 浏览器：**无痕窗口**（sessionStorage 里没有上次的令牌，不会误点写按钮）、缩放 125%（投影仪上 12px 的字看不清）、侧栏"总览"高亮说明前端连上了。
- [ ] 提前开好 4 个标签页并**加载完**（现场网络慢不慢和你无关，页面已经在内存里）：
  1. `http://localhost:3000/`
  2. `http://localhost:3000/leaderboard?set=benchmark-cn-v1&version=v2`
  3. `http://localhost:3000/runs/167`
  4. `http://localhost:3000/task-runs/2444`
- [ ] 兜底材料在手边：录屏文件（§4.1）、数据库快照（§4.2）、接口清单（§4.3）。
- [ ] 手机静音，关掉桌面通知。

## 1. 主线（5 分钟）

每步给了**要点几句台词**和**屏幕上该看到的数字**。数字对不上先别慌——按 §0 核过就不会；对不上说明库被动过，改口说"以现场为准"。

### 第 0 步 · 首页总览（20 秒）

`http://localhost:3000/`

看到：**数据集 3 个 · 6 版（最新版合计 138 题）**、**参赛 Agent 3 个（5 条启用配置）**、**实验运行 56 次**、**正在跑 0 个**、最近 5 次实验（#170 → #166，E10-T4 第 2 轮）。

台词：

> 平台做的事一句话：从开源项目挑一个已经被修好的 bug，把代码回退到修复前，把当时的 issue 交给 AI，用项目自己的测试验证它修没修好。
> 现在库里 3 个数据集、3 个参赛 Agent、跑了 56 次实验。下面沿一条线走：榜 → 实验 → 每道题 → 一道题的证据。

### 第 1 步 · 排行榜，切到中文集（60 秒）

点侧栏"排行榜"，页面默认是最新发布的 `swebench-verified-subset@v3`（官方题）。**用数据集下拉切到 `benchmark-cn-v1@v2`**——中文题面、41 道、自建。

看到（按解决率排）：

| 名次 | 参赛者 | 解决率（两轮均值） | 两轮 | 每题成本 |
|:--|:--|--:|:--|:--|
| 1 | claude-code@deepseek-flash | **76.8%** | 75.6% / 78.0%（极差 2.4 pp） | $0.027（下界，有 2 次报不出） |
| 2 | miniagent@deepseek-flash（自研） | **28.0%** | 26.8% / 29.3% | $0.010 |
| 3 | aider@deepseek-flash | **14.6%** | 14.6% / 14.6% | $0.010（下界） |

榜下面"被排除的实验"两行：#157（aider 开了思考模式，和别人条件不同，留作对照）、#160（判定引擎漏洞导致 5 道题误记平台故障，作废，由 #161 重跑替代）。

台词：

> 一个数据集版本一张榜，不同数据集之间不比。三个参赛者底座都是同一个模型 deepseek-flash，比的是 Agent 外壳。
> 每个数字是两轮的均值，旁边写着两轮各多少、差多少——单轮结果不能当结论，我们实测过换一轮能差好几个点。
> 成本那列 claude-code 标着"下界"（散点图里是空心点）：它有两次报不出成本，我们只加报得出的部分、不把缺的算成 0——算成 0 它就成了"最便宜"。
> 榜的底部列出被排除的实验和理由。**一个不说自己筛掉了什么的排行榜没法复核。**

可选：把指标切到"成本"，看成本-解决率散点。

### 第 2 步 · 一次实验（60 秒）

点 claude-code 那行右侧的 **#167** → `/runs/167`。

看到：`E10-T4 第 2 轮 · claude-code · benchmark-cn-v1@v2`，状态**已完成**，41/41，严格解决率 **78.0%**，平台故障 **0**，`dirty = false`。下面是按结论分组的逐题网格：**已解决 32 · 未解决 9**（9 个里 6 个是「未解决」、3 个是「空补丁」，悬停每一格能看到）。

台词：

> 一次实验 = 一个参赛者 × 一版数据集跑一轮。每道题的结果用三个互相独立的字段记：走到哪一步了、**平台**有没有正确完成、**AI** 有没有修好。
> 平台故障（比如容器被 OOM 杀了）不记在 AI 头上，会重试；AI 没修好才算它的。这两种混进一个字段，解决率就不可信——这是整个协议最核心的一条。
> `dirty = false` 是说跑的时候代码库干净、结果绑定一个 git commit，能复现。

### 第 3 步 · 逐题网格，点一格（30 秒）

在"未解决"那组找 **`click-3225`**，鼠标悬停有摘要，点开。

台词：

> 网格每一格一道题，颜色是结论。任何页面三次点击之内都能到"某个 AI 在某道题上为什么失败"的完整证据——这一格点进去就是。

### 第 4 步 · 单题证据（120 秒）

`/task-runs/2444`：`click 8.3.0 里用类当 flag_value 时，默认值会被实例化`，徽章**未解决**。

从上往下：

1. **统计条**：F2P **5 / 5**，P2P **1311 / 1315**。
   > F2P 是修复前失败、修好后必须通过的用例——5 条全过了，目标 bug 是修好了的。但 P2P 是不许改坏的用例，1315 条里挂了 4 条。**修好一个、弄坏四个，判未解决。** 判定 100% 由测试结果推导，不用大模型，今天判和下个月判结论一样。
2. **补丁**：改了 1 个文件。"标准化后"和"AI 原样"两份可切换。
   > 标准化是把 AI 对测试文件、配置文件的改动过滤掉——否则把测试改成 `assert True` 就"通过"了。
3. **逐条用例**：角色切 P2P、状态切失败，看那 4 条挂掉的用例和报错。
   > 这是判定的原始依据，逐条可查。
4. **日志 / Agent 轨迹**：轨迹时间线 41 轮工具调用。
   > 它是怎么想的、改了几次，都在这。
5. **失败归因**：红色徽章 **F6 · 引入回归**，"规则层 · 可信"，判据 `f2p 5/5 · p2p 1311/1315`。
   > 归因回答"为什么没修好"。F6/F7/F8/N1 这四类规则就能判、不花钱；"改了但没修对"那几类要大模型或人工。**归因只解释原因，不改判定**——上面那个"未解决"来自测试，这里的 F6 来自归因，两者独立。

### 第 5 步 · 收尾（30 秒）

回到 `/benchmarks/benchmark-cn-v1?version=v2`，指门禁证据：**Oracle 41 / 41、Noop 0 / 41**。

台词：

> 每版数据集发布前过两道门：用官方补丁跑必须 100%，用空补丁跑必须 0%。不是 100% 说明题坏了或判定有 bug，不是 0% 说明题在修复前就已经通过。榜上的数字建立在这两个哨兵之上。

## 3. 提问准备

答案的细账都在 `docs/plan/`，这里只写一句话版本。

- **为什么不用大模型判 bug 修没修好？** 判定要可复现——同一个补丁今天判和下个月判必须一样，否则排行榜不可比。大模型只用来分析"为什么没修好"，而且它的输出不回写判定（协议 C-40）。
- **三个字段为什么分开？** "AI 没修好"和"我们的 Docker 崩了"是相反的结论。混进一个字段，平台一抖，AI 的解决率就掉，没人看得出来。
- **两轮差多少？可信吗？** 极差 ≤ 4 个百分点；逐题看有 17–43% 的题两轮结论不同，补丁指纹比对证明翻转全来自 AI 自己的不确定性，判定是确定的（`03-benchmark-spec.md` §8.13，Oracle 三次 / Noop 一次、116 题逐条一致）。
- **怎么防 AI 翻到官方修复？** 工作区用 `git archive` 导出文件树再 `git init`，只有一个 commit，没有历史可翻；测试容器断网。
- **OOM 和超时都是退出码 137，怎么分？** 用 `docker inspect` 的 `OOMKilled`。并发下有 3–5% 漏报，只告警不改判（`05-sandbox.md` §10.10）。
- **成本怎么算的？** Agent 自报优先，报不出按 token × 牌价估，估不了标"拿不到"——三种来源分开显示，不合并。
- **哪些没做？** MinIO（抽象层就绪，本地存储顶着）、Harness Replay（用确定性哨兵和补丁指纹代替）、大模型归因没跑真模型（177 道待判，估算几块钱）、盲检的准确率 / κ 统计（原始标签表已就位）。报告里主动写"未做 + 原因"，不留空（`11-acceptance-testing-risk.md` §26.2）。

## 4. 兜底

### 4.1 录屏

演示前一天按 §1 完整录一遍，**再把每一步单独录一段**（现场只挂一步时能只放那一段）。

- Windows 自带：`Win + Alt + R` 开始 / 停止（Xbox Game Bar），文件在 `视频\捕获`；要录整个桌面用 OBS。
- 1080p、系统声音关掉、鼠标指针要录进去。
- 存两份：U 盘一份，云盘一份；开场前在演示机上**播放一次**确认解码器没问题。

### 4.2 数据库快照

演示前一天导一份，库被动了（比如有人跑了测试——集成测试会**清空**它连的库）能 5 分钟恢复：

```bash
mkdir -p var/backup && docker exec bench-postgres pg_dump -U bench -Fc bench > var/backup/bench-2026-09-21.dump
```

约 27 MB（`var/` 不进 git，跟制品一起拷走）。恢复（先把后端停掉，`--clean` 要重建表，有连接挂着会卡住）：

```bash
docker exec -i bench-postgres pg_restore -U bench -d bench --clean --if-exists --no-owner < var/backup/bench-2026-09-21.dump
```

制品（补丁正文、日志、轨迹）在 `var/artifacts/`（约 300 MB），单题页的补丁 / 日志 / 轨迹从这里读，**要一起备份**；只恢复库不拷制品，页面上补丁和日志会 404，判定和归因照常。

### 4.3 故障树

| 现象 | 怎么办 |
|:--|:--|
| 前端起不来 / 白屏 | 用 `http://localhost:8000/docs`（接口文档，能点着试）沿同一条线讲：`/api/leaderboard?set=benchmark-cn-v1&version=v2` → `/api/runs/167` → `/api/runs/167/task-runs?status=COMPLETED` → `/api/task-runs/2444`、`/api/task-runs/2444/tests?role=P2P&status=FAILED` |
| 后端起不来 | 放录屏。别当场修，答辩不是排错现场 |
| 数据库数字不对 / 表空了 | 恢复 §4.2 的快照（2 分钟），或直接放录屏 |
| 单题页"失败归因"显示"盲检进行中" | `.env` 里 `BENCH_BLIND_REVIEW` 被打开了，改成 `false` 重启后端；来不及就口头说明这是抽检期间的开关 |
| 投影上字太小 | 浏览器缩放 150%；表格会横向滚动，不会挤成竖排 |
| 演示机整个不行 | compose 部署的副本可以顶上（`docs/deployment.md`，`make compose-up` 几十秒），库用 §4.2 的快照恢复 |

### 4.4 时间控制

主线 5 分钟：0.3 + 1 + 1 + 0.5 + 2 + 0.5。超时先砍第 5 步（门禁）和第 4 步的日志 / 轨迹两段，**第 4 步的统计条和归因不能砍**——"修好一个弄坏四个所以判未解决"是整场最有说服力的一句话。
