# 打折之后每单少收一分钱

## 现象

财务对账时发现，带折扣的订单实收金额比应收少，差额稳定是 1 分。不带折扣的订单没问题。

追下去定位到 `cart.pricing.discounted_cents()`。商品原价 995 分（9.95 元）打九折，应该是 895.5 分，按四舍五入收 896 分，但函数返回的是 895。

## 复现步骤

```python
from cart.pricing import discounted_cents

print(discounted_cents(995, 10))
```

期望输出 896，实际输出 895。

## 影响

促销期间大部分订单都带折扣，单笔差一分，一天几万单就是几百块的缺口，而且对账流水每条都不平，财务同事要手工核销。

## 顺带发现的第二个问题

这个函数对折扣百分比完全不校验。传 120 会算出负数金额，传 -5 会算出比原价还高的金额。上游接口理论上不会传这种值，但既然是算钱的函数，非法输入应该直接报错，不要静静地算出一个离谱的数。

## 期望行为

不足一分的部分按四舍五入处理，而不是直接截断。折扣百分比超出 0 到 100 的范围时抛 `ValueError`。已有的整数倍折扣（比如 1000 分打九折得 900）结果不要变。
