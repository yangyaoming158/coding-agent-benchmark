# 第 0 页返回的是最后一页的数据

## 现象

前端有个筛选组件在清空条件时会把页码重置成 0 再请求一次列表。这时候接口返回的不是空列表，而是**最后一页**的内容，用户看到的是列表末尾的几条记录，还以为自己的数据只剩这么多。

定位到 `pager.paginate.page_slice()`。页码从 1 开始数，`page=0` 算出来的起始下标是 -3，Python 的负数切片从列表尾部取值，于是就取到了最后三条。

## 复现步骤

```python
from pager.paginate import page_slice

print(page_slice([1, 2, 3, 4, 5, 6, 7], 0, 3))
```

期望是报错，实际输出 `[5, 6, 7]`。页码传 -1 也是类似的结果。

## 影响

不会报错，只是数据不对，所以线上跑了两个月没人发现，是用户来问"我的记录怎么少了"才查出来的。这种静默错误比直接抛异常难查得多。

## 顺带发现的第二个问题

`page_slice()` 对每页条数也不校验。传 0 会返回空列表，而同一个模块里的 `page_count()` 遇到 0 是抛 `ValueError` 的。同一个参数在两个函数里行为不一致，调用方没法写统一的错误处理。

## 期望行为

页码小于 1 时抛 `ValueError`。每页条数不是正数时也抛 `ValueError`，和 `page_count()` 保持一致。页码超出总页数时仍然返回空列表 —— 这个行为是对的，不要改。
